# Known issues

Symptom first, then the root cause in the code, then what to do. Add an entry when you find a problem you cannot fix right away; remove it in the commit that fixes it.

| # | Symptom | Root cause | Where | Status / next step |
|---|---|---|---|---|
| 1 | Agentic answers use little of what the agent found; more MCP research barely changes the answer | Only the agent's evidence ids reach the pipeline, capped at `HARNESS_AGENTIC_MAX_MCP_SEEDS` (6, one per paper first). Its findings and summary are dropped, and the pipeline repeats retrieval and extraction. | `harness_agent/research.py` (`_select_seeds`, `_run_shared_pipeline`) | Plan phase 3b: scratchpad hand-off (findings with ids passed to the pipeline). |
| 2 | `verified_claim_ids` is always empty | The agent runs before the pipeline, so there are no preliminary claims to confirm (`_grounded_context(None, ...)`). | `harness_agent/research.py` | Resolved by the same hand-off redesign (phase 3b). |
| 3 | Some concept readings show "0 corpus passages" | Concepts are proposed first and grounded afterwards; grounding searches each LLM search term as an exact quoted phrase, and multi-word phrases rarely match. Ungrounded concepts are still shown to reach the minimum of 3. | `harness_agent/concepts.py` (`_ground`) | v2 prompt asks for 1–3 word terms (mitigation). Fix in phase 3a: retrieve first with ranked BM25, then propose. |
| 4 | Heavy keeps working after a run is stopped or times out; later runs are slow | A stopped run abandons its model call, but a non-streaming request cannot be cancelled: in LiteLLM 1.102 only streaming requests react to a client disconnect, so the upstream vLLM generation runs to the end. | `harness_extraction/call_control.py`, `model_client.py` | Set `HARNESS_MODEL_STREAM=true`: the client then closes the stream on Stop and LiteLLM/vLLM abort the generation. Verify on the node (watch `running` in `/v1/status` drop after Stop), then make it the default. The agent tool loop (`mcp.py`) is not streamed yet. |
| 5 | Heavy is overloaded when the agent runs on Lite | The heavy-busy deferral only applies when the agent model is the high model; with Lite as agent, only `HARNESS_MAX_CONCURRENT_HEAVY` bounds Heavy. | `harness_agent/research.py` (`_check_heavy_load`) | Decide in phase 3 whether pipeline Heavy calls should wait on `/v1/status`. |
| 6 | Heavy latency spikes under parallel runs | Heavy's KV cache held about 69k tokens (2.1 full 32k requests) with the model dtype; long requests beyond that are preempted. | thesis-llm-setup `profiles/a100-3x40.yaml` | FP8 KV cache enabled on Heavy (restart required). Check `preemptions` in `/v1/status`; load test before raising limits. |
| 7 | The `extraction/triple_extraction` prompt has no effect on live runs | The API builds every runner with `edc=True`, so extraction always uses the EDC prompts; `extract()` runs only when `edc=False`. | `api/runtime.py` (`_runner`), `harness_baseline/research_steps.py` | Keep the prompt for the non-EDC mode; do not tune it expecting live changes. |
| 8 | Precision/recall panel ("Interpretation") is empty | No approved gold rows for the questions yet. The scorer (strict / entailed / soft, vital recall, judged precision, complexity × path) and `make evaluate` are in place. | `labelling`, `harness_evaluation`, `api/routes_benchmark.py` | Phase 2: first gold batch; the UI panel still has to show the new fields. |
| 9 | Gold scoring penalises correct claims with invented predicates | Gold uses DBLP vocabulary only; the live system may invent `hrn:` predicates. | `harness_evaluation`, `labelling` | Mitigated: DBLP predicates are scored locally closed, invented ones via the entailed level (`datasets/ontology/predicate_relations.ttl`, still without invented-predicate rules) and judged precision. Rules must be added as invented predicates appear. |
| 10 | Structured replies sometimes fail to parse | Calls request `response_format: json_object`, which does not enforce the schema. | `harness_extraction/model_client.py` | Candidate: vLLM structured outputs with `json_schema` from the Pydantic models; measure on gold first. |
